ตารางกฎตัวคัด Ranking

Ranking list แสดงเฉพาะชื่อที่ผ่านตัวคัดที่ผู้ใช้เปิดไว้เท่านั้น
ตัวคัดที่เปิด เงื่อนไขที่ชื่อต้องผ่าน ผลต่อรายการ แกน tie-break
คัดเลขศาสตร์ดี is_sat_good = true แสดงเฉพาะชื่อที่ผ่าน SAT แล้วเรียงตามคะแนนอันดับ sat_pair_type และ sat_pair_point
คัดพลังเงาดี is_sha_good = true แสดงเฉพาะชื่อที่ผ่าน SHA แล้วเรียงตามคะแนนอันดับ sha_pair_type และ sha_pair_point
✅ เปิดทั้งสอง is_sat_good = true และ is_sha_good = true ชื่อที่ไม่ผ่านอย่างใดอย่างหนึ่งจะไม่เข้า ranking list ใช้ final score ก่อน แล้วดูคุณภาพ SAT/SHA ประกอบ
ยังไม่เปิดตัวคัด ยังไม่มี ranking criteria ระบบแสดงไอเดีย/คำแนะนำชื่อ ไม่แสดงอันดับ ยังไม่ใช้ ranking tie-break

ลำดับการเรียงคะแนน

ลำดับ ข้อมูลที่ใช้ ใช้เมื่อใด เหตุผล
1 final_rank_score เมื่อ backend ส่งค่ากลับมา เป็นคะแนนกลางที่ทำให้ web และ mobile เรียงอันดับตรงกัน
2 local calculated score เมื่อไม่มี final_rank_score ใช้ semantic, numerology, pair bonus, กาลกิณี และความยาวเป็น fallback
3 D10 / D8 / D5 เมื่อคะแนนอันดับเท่ากัน คู่เลขที่แข็งแรงกว่าควรขึ้นก่อนชื่อที่คะแนนรวมใกล้กัน
4 pairpoint เมื่อ pairType เท่ากัน คะแนนคู่เลขละเอียดช่วยแยกชื่อที่อยู่ใน tier เดียวกัน
5 semantic score ท้ายสุด ใช้ตัดสินเมื่อคุณภาพชื่อและคู่เลขใกล้กันมาก

ตัวคัดและ Double Lucky

ตัวคัดในระบบ ranking เป็น ประตูเข้าอันดับ ไม่ใช่แค่ป้ายบอกคะแนน เมื่อคุณเปิดตัวคัดแล้ว ชื่อที่ไม่ผ่านเงื่อนไขนั้นจะไม่ถูกนำมาแสดงใน ranking list

1. เลือกหนึ่งตัวคัด
เปิด คัดเลขศาสตร์ดี ระบบใช้ SAT เป็น gate หรือเปิด คัดพลังเงาดี ระบบใช้ SHA เป็น gate แล้วเรียงชื่อที่ผ่านตามคะแนนอันดับ
2. เปิดทั้งสองตัวคัด
ชื่อต้องผ่านทั้ง เลขศาสตร์ดี และ พลังเงาดี จึงจะเข้าอันดับได้ ชื่อที่ผ่านทั้งสองมักได้แรงส่งจาก double bonus ในคะแนนรวม

เมื่อผู้ใช้ระบุนามสกุล หรือ ค้นหาชื่อคู่ ระบบจะยังยึดหลักเดียวกันคือ กรองตามเงื่อนไขก่อน แล้วจึงจัดอันดับ เพียงแต่คะแนนที่แสดงบนการ์ดจะมีทั้งคะแนนชื่อเดี่ยวและคะแนนรวมชื่อ+นามสกุล:

ลำดับขั้น กระบวนการ (Flow) ผลลัพธ์
1. ตั๋วเข้าชิง (Filter) ระบบคัดชื่อตามปุ่มที่เปิดไว้ เช่น SAT, SHA หรือทั้งสองแบบร่วมกัน และในโหมดชื่อคู่จะตรวจคะแนนรวมชื่อ+นามสกุลประกอบด้วย ชื่อที่ไม่ผ่านเงื่อนไข active จะไม่เข้า ranking list
2. จัดอันดับ (Ranking) นำชื่อที่ผ่าน gate มาเรียงด้วย final_rank_score ก่อน หากคะแนนเท่ากันจึงดู pairType, pairpoint และ semantic score ตามลำดับ อันดับ 1 คือชื่อที่ผ่านเงื่อนไขและมีคะแนนจัดอันดับดีที่สุด ไม่ใช่แค่ความหมายใกล้ที่สุดอย่างเดียว
3. แบนชื่อซ้ำ รายชื่อเข้ารอบ ที่มีตัวสะกดเหมือนกับ นามสกุล หรือ ชื่อตั้งต้น แบบ 100% จะถูกนำออกจาก Candidate ทันที (Exclude) ป้องกันไม่ให้ผลลัพธ์แนะนำชื่อเดิม แบบซ้ำซ้อน (เช่น ค้นหาคู่ให้ "ณเดชน์" จะไม่มีชื่อ "ณเดชน์" โผล่มาเป็นคนแรกอีก)
ทำไมยังต้องใช้ความหมายร่วมกับเลขศาสตร์?
เพราะชื่อที่ดีควรผ่านทั้งสองด้าน: ความหมายต้องใกล้สิ่งที่ผู้ใช้ต้องการ และ เลขศาสตร์/พลังเงาต้องผ่านตัวคัดที่เลือก ระบบจึงไม่ให้ semantic score เอาชนะชื่อที่ไม่ผ่าน gate และไม่ให้เลขดีอย่างเดียวขึ้นนำโดยไม่สัมพันธ์กับความหมาย

กาลกิณีกับการจัดอันดับ

กาลกิณีคือตัวอักษร (สระ / พยัญชนะ / วรรณยุกต์) ที่ถือว่า "ไม่เป็นมงคล" ตามวันเกิด ระบบใช้ข้อมูลจากตาราง kakis_day ใน Database โดยมี 8 วัน ได้แก่ อาทิตย์ จันทร์ อังคาร พุธ(กลางวัน) พุธ(กลางคืน) พฤหัสบดี ศุกร์ เสาร์

การ Highlight สีแดง (Canvas Rendering)
ระบบใช้ HTML5 Canvas Single-Pass วาดชื่อทีละตัวอักษร เพื่อให้ ตัวการันต์ (์) และสระที่เป็น Combining Mark แสดงสีแดงแยกจากพยัญชนะได้ — เพราะถ้าใช้ <span> ปกติ Browser จะ compose glyph แล้วใช้สีของพยัญชนะ ทำให้ Custom highlight ไม่ทำงาน

ขั้นตอนการทำงาน (ใน < 2 วินาที)

1
สร้างแม่แบบชื่อ
ระบบรับชื่อหรือความหมายที่คุณกรอก แล้วสร้างแม่แบบชื่อที่ใช้ค้นหาและจัดอันดับได้
2
สร้าง Vector Embedding
แปลงความหมายสรุปให้เป็น Vector 1536 มิติ เพื่อใช้เปรียบเทียบความหมายกับชื่อในฐานข้อมูล 301,000+ รายการ
3
Hybrid Search (UNION KNN)
ค้นหาพร้อมกัน 2 วิธีคือ Vector Similarity (ความหมาย) และ Trigram (รูปแบบตัวอักษร) แล้ว UNION รวมกันได้ผู้สมัคร 200 ชื่อ
4
คัด SAT/SHA ตามปุ่มที่เลือก
ชื่อต้องผ่านเลขศาสตร์ดีหรือพลังเงาดีตามเงื่อนไขที่เปิดไว้ ถ้าเปิดทั้งสอง ต้องผ่านทั้งสองก่อนเข้า ranking list
5
เรียงด้วย final_rank_score
ใช้คะแนนจาก backend เป็นหลัก แล้ว tie-break ด้วย D10/D8/D5, pairpoint และ semantic score เพื่อให้ลำดับไม่ขัดกับคุณภาพชื่อที่ผู้ใช้เห็น
