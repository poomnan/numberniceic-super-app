# Thai Wedding Date Logic (ฤกษ์แต่งงาน) — Developer Knowledge Base

> อัปเดตล่าสุด: เมษายน 2569 / April 2026  
> แหล่งที่มา: RengYamF.kt (Android)

---

## 1. เกณฑ์การคำนวณพื้นฐาน

ระบบค้นหาฤกษ์แต่งงานจะพิจารณาจากข้อมูลวันเกิดและเวลาเกิดของทั้ง **เจ้าบ่าว** และ **เจ้าสาว** โดยมีหลักการสำคัญดังนี้:

### 1.1 การนับวันทางโหราศาสตร์ไทย (Boundary)
- **ตัดวันเวลา 06:00 น.** (ไม่ใช่เที่ยงคืน)
- **วันพุธกลางคืน:** เริ่มตั้งแต่ 18:00 น. ถึง 05:59 น. ของเช้าวันพฤหัสบดี
- ตัวอย่าง: เกิดวันที่ 1 เมษายน เวลา 02:00 น. ทางโหราศาสตร์ยังถือว่าเป็นวันก่อนหน้า

### 1.2 การระบุวันเกิด (Birth Day Number)
ใช้ฟังก์ชัน `calculateOutfitBirthDayNumber` เพื่อแมปวันเกิดเป็นตัวเลข 1-8:
- 1: อาทิตย์
- 2: จันทร์
- 3: อังคาร
- 4: พุธ (กลางวัน)
- 5: พฤหัสบดี
- 6: ศุกร์
- 7: เสาร์
- 8: พุธ (กลางคืน)

## 2. กฎวันอัปมงคล (Red Days)

แต่ละวันเกิดจะมี "วันอัปมงคล" ประจำตัว ซึ่งระบบจะห้าม (Exclude) ไม่ให้แนะนำฤกษ์ที่ตรงกับวันเหล่านี้

### 2.1 Fixed Bad Days (ตามวันเกิด)
| วันเกิด (เลข) | วันอัปมงคลที่ห้าม (Fixed) |
|-------------|-------------------------|
| 1 (อาทิตย์) | ศุกร์, อังคาร |
| 2 (จันทร์) | อาทิตย์, พฤหัสบดี |
| 3 (อังคาร) | จันทร์, อาทิตย์ |
| 4 (พุธ กลางวัน) | อังคาร, พุธ (กลางคืน) |
| 5 (พฤหัสบดี) | เสาร์, จันทร์ |
| 6 (ศุกร์) | พุธ (กลางคืน), เสาร์ |
| 7 (เสาร์) | พุธ (กลางวัน), ศุกร์ |
| 8 (พุธ กลางคืน) | พฤหัสบดี, พุธ (กลางวัน) |

### 2.2 Transit Bad Days (กาลกิณีอายุย่าง)
- คำนวณจาก **ทักษาปกรณ์** โดยพิจารณาตามอายุย่างของเจ้าบ่าว/เจ้าสาวในขณะนั้น
- ระบบจะดึง "กาลกิณี" (Kalagni) ประจำวัยมาเป็นวันต้องห้ามเพิ่มเติม
- ตัวอย่าง: เจ้าบ่าวเกิดวันอาทิตย์ อายุย่าง 45 ปี วันกาลกิณีคือ "พุธกลางคืน"

## 3. เกณฑ์การคัดเลือกวัน (Selection Criteria)

ฟังก์ชัน `isEligibleForCategory(wp, "marriage")` ใช้เกณฑ์ดังนี้:

1. **ไม่เป็นวันเสียส่วนรวม (Hard Negative):** ห้ามตรงกับ วันอุบาทว์, โลกาวินาศ, วันจม ฯลฯ
2. **เป็นวันดีอย่างน้อยหนึ่งอย่าง:**
   - เป็นวันมงคลทั่วไป (ธงชัย, อธิบดี, อำฤตโชค, ฯลฯ)
   - **หรือ** เป็น "วันปลอด" (Plain Safe Day - วันที่ไม่เสียและไม่เด่น)
   - **หรือ** เป็น "ดิถีเรียงหมอน" (Riang Mon)
3. **ไม่มี Warning เฉพาะเจาะจง:** ห้ามมีคำเตือนที่ระบุว่าห้าม "สตรี" หรือ "บุรุษ" (เช่น อัคนิโรธบางหมวด)
4. **ไม่ตรงกับ Red Days ของบ่าว-สาว:** (ตามข้อ 2.1 และ 2.2)

## 4. ขั้นตอนการค้นหา (Search Workflow)

1. **Input:** รับวัน/เวลาเกิดบ่าวสาว → คำนับวันเกิด (1-8) และอายุย่าง
2. **Generate Red Days:** รวมรายการวันห้ามของทั้งสองฝ่าย (เช่น ["ศุกร์", "อังคาร", "จันทร์"])
3. **Scan Months:** ไล่ตรวจสอบทีละวันในปฏิทิน (สูงสุด 12 เดือน)
4. **Validation:**
   - เช็ค `isEligibleForCategory` ในระดับ Global
   - เช็คว่าชื่อวันนั้นๆ (เช่น "ศุกร์") ไม่ติดอยู่ใน Red Days List
5. **Collect:** เก็บวันแรกที่พบ 7 วันแรก
6. **Result:** แสดงผลบน Bottom Sheet พร้อมหมายเหตุการคำนวณ (Calculated Note)

## 5. ข้อระวังสำหรับ Developer

1. **isSameKalagniDay:** เวลาเปรียบเทียบชื่อวัน ต้อง Normalize ชื่อให้ตรงกัน (เช่น "พุธกลางคืน" vs "พุธ (กลางคืน)")
2. **RengYam Access:** ระบบค้นหาฤกษ์แต่งงานต้องเช็ค Priority/Permission (VIP) ก่อนแสดงผลลัพธ์
3. **Persistance:** ข้อมูลวันเกิดบ่าวสาวจะถูกบันทึกลง SharedPrefs (`last_marriage_groom_date` ฯลฯ) เพื่อให้ User ไม่ต้องกรอกใหม่
4. **Marriage Note:** `marriageSearchNote` เป็น `SpannableStringBuilder` เพื่อแสดงไฮไลท์สีส้ม (มงคล) และสีแดง (อัปมงคล) ใน UI
